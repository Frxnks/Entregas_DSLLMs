● Answered Claude's questions:
  ⎿  · ¿Qué significa el puntaje y cómo se usan los umbrales? (el requerimiento
     no lo define) → Un puntaje alto significa más confianza. Cada cliente tiene
     un umbral de aprobación: si el puntaje es mayor o igual al umbral, se
     aprueba; si es menor, se deriva a revisión. MIRA nunca rechaza un caso por
     sí sola, así que RECHAZAR no es una decisión automática válida. Además,
     cada cliente tiene un mínimo por señal: si alguna señal tiene un puntaje
     menor a ese mínimo, el caso se deriva aunque el promedio alcance el umbral.
     Ambos valores van en escala 0 a 100 y son propios de cada cliente.
     · ¿Cómo llega el puntaje y las señales de fraude al módulo? → El puntaje
     del caso es el promedio simple de los puntajes de sus señales, en escala 0
     a 100. Si el caso llega sin señales, MIRA no decide sola: lo deriva a
     revisión. Una señal de fraude es una señal marcada explícitamente como
     fraude.
     · Si hay señal de fraude, ¿cuál es el resultado y qué pasa con la
     configuración por cliente? → Si el caso tiene al menos una señal de fraude,
     siempre se deriva a revisión, sin importar el puntaje. Nunca se rechaza
     automáticamente. Si el cliente no tiene umbrales configurados, MIRA no
     decide y responde un error que indica que falta la configuración del
     cliente. No se usan valores por defecto.

● MIRA ya decide sola entre aprobar y derivar a revisión, y las 22 pruebas pasan
  con Python 3.12.10 en el entorno .venv. Hay una advertencia de deprecación de
  Starlette sobre httpx, que no afecta el resultado.

  Reglas implementadas, según tus respuestas:
  - Decisiones posibles: solo APROBAR y REVISION. MIRA nunca rechaza.
  - Puntaje: el promedio simple de las señales, de 0 a 100.
  - Fraude: cualquier señal marcada como fraude deriva a revisión, aunque el
    puntaje sea 100.
  - Sin señales: deriva a revisión.
  - Aprobación: el promedio debe ser mayor o igual al umbral de aprobación del
    cliente.
  - Mínimo por señal: si alguna señal queda bajo el mínimo del cliente, deriva
    aunque el promedio alcance el umbral.
  - Sin configuración del cliente: responde 404 con client_config_missing y no
    decide. No hay valores por defecto.

  Para tu revisión:
  - Sin configuración y con fraude: el error de configuración faltante tiene
    prioridad, incluso si el caso trae fraude o no trae señales. Lo interpreté
    así porque dijiste que en ese caso MIRA no decide. Si prefieres que el
    fraude derive igual, es un cambio pequeño.
  - Persistencia: las configuraciones viven en memoria y se pierden al reiniciar
    el servidor. No dijiste nada sobre guardarlas.
  - Señales de fraude: cada señal de fraude debe traer también un puntaje, y ese
    puntaje entra en el promedio.

  API:
  - PUT /clients/{id}/config guarda {approval_threshold, min_signal_score},
    ambos de 0 a 100.
  - GET /clients/{id}/config devuelve esa configuración.
  - POST /clients/{id}/decision recibe {signals:[{name, score, is_fraud}]} y
    devuelve {decision, score, reasons}.

  Para levantarla: .\.venv\Scripts\python.exe -m uvicorn mira.api:app. Antes hay
  que instalar uvicorn, que no incluí porque las pruebas no lo necesitan.
